## Purpose

When a user texts/pastes one of our shareable URLs into iMessage, WhatsApp, Slack, etc., the
messaging app's crawler reads the page's `<head>` for Open Graph tags and renders an **unfurl
preview**. Today every one of our links previews as the generic **"function bucket"** — because no
page sets any `og:*`/`title` meta, and the one page that *has* a per-link label
(`/auth/go/[id]`) fetches it **client-side** (`onMounted`), where an unfurl bot — which runs no
JS — never sees it.

This spec gives shared links a **meaningful preview** — `Poll: Favorite color?`,
`Todo: Buy milk`, `You've been invited to Function Bucket` — by (1) rendering the label into
`<head>` **server-side** so crawlers see it, and (2) formatting it from a single **per-module
presentation registry** so every current and future module is consistent and gets its preview for
free.

**This is a `<head>`-metadata feature — it adds no visible in-app UI.** The preview only ever
appears *outside* the app, in another program's link card. That is why this spec has `.data.md`
files but **no `.ui.md` files** (deliberate — there is no rendered surface to describe).

## Locked decisions (2026-08-07)

| # | Decision | Why |
|---|---|---|
| L1 | **Scope = OTP deep links (`/auth/go/<id>`) + invite ceremony links** (`set-password`, `verify-email`). Raw in-app detail links and asset links are **out** (behind auth — a crawler sees the login redirect, not the item; only a browser-tab nicety). | User scope pick. The two in-scope surfaces are the ones actually texted to people who aren't logged in, so the crawler reaches a real public page. |
| L2 | **Preview text = noun + title everywhere**: `Poll: {label}` · `Todo: {label}` · (future) `Approval: {label}`. Title omitted → the noun alone (`Todo`). | User wording pick. Uniform `Module: title`, predictable across modules; the title is already sharer-chosen and already shown on the landing page, so no new disclosure. |
| L3 | **The module prefix + icon + description live in a per-module presentation registry** — extend `apps/auth-app/shared/utils/urn-route.ts` from `module → route` to `module → { route, previewNoun, icon, ogDescription }`. `auth.deep_link.subject_label` stays the **bare** name (`Buy milk`); the landing page composes `Todo: Buy milk`. | Single source of truth for per-module presentation, colocated with the route map it already parallels. Future modules (approval, @mention, guest) get route **and** preview from one edit. Keeps the cached label non-presentational. |
| L4 | **OTP preview is SSR-rendered**: the `/auth/go/[id]` public-projection fetch moves from `onMounted` to `useAsyncData` (runs on the server), and `useSeoMeta` reads it. The interactive/logged-in state logic stays client-side, unchanged. | Unfurl crawlers don't run JS — the og tags must be in the server response HTML. The public projection (`app_fn.get_deep_link`) is already enumeration-safe and already exposes exactly `{ subjectLabel, module, expired, revoked }`. |
| L5 | **Preview description carries NO tenant/workspace name** — only module + `subjectLabel` + a generic call-to-action ("Log in with a one-time code to view and respond."). | `app_fn.get_deep_link` deliberately hides the tenant id/name for enumeration safety (otp-login §10); the preview must not reintroduce it into unfurl caches / forwarded messages. |
| L6 | **Invite preview is STATIC / generic** — a branded card on `set-password.vue` + `verify-email.vue` set from constants, with **no token read** and **no consumption**. Threading the org/inviter name into the preview is a **follow-on** (would require the invite-user n8n workflow to append a non-sensitive label param). | The ceremony URL only consumes its `code` on **POST**; a GET (bot prefetch) just renders the form, so a static og card is zero-risk. A generic "You've been invited to Function Bucket" already beats "function bucket"; per-invite data is an opt-in enhancement, not v1. |
| L7 | **`og:image` = a single branded default asset** (logo/wordmark), same for every link; `[FILL IN]` the asset path against `docs/specs/brand-identity/`. No per-item images. | A card with an image renders far better than a bare title; a static brand image needs no per-request work and leaks nothing. |

## Considered & rejected
- **Formatting the label at share time** (caller stores `"Poll: X"` in `subject_label`) — rejected
  (L3): scatters wording across every caller and makes the cached label presentational. The registry
  keeps one source of truth and a bare, reusable label.
- **Setting og tags client-side** (in `onMounted`/`useSeoMeta` after the client fetch) — rejected
  (L4): unfurl crawlers don't run JS, so the tags must be server-rendered.
- **Including the workspace name in the preview** — rejected (L5): `get_deep_link` hides the tenant
  for enumeration safety; the preview must not reintroduce it into forwarded messages / unfurl caches.
- **Per-item `og:image`** (e.g. a poll chart) — rejected for v1 (L7): needs per-request image
  generation for marginal gain; a static brand image renders well and leaks nothing.
- **Previews on raw in-app detail / asset links** — rejected (L1): they sit behind auth, so a
  crawler sees the login redirect, not the item; the only benefit is the browser tab title.
